# REAmon feature matrix

This matrix describes product capabilities, not a promise that every engine or input
works for every artifact. “Implemented” means a workflow exists in the current
checkout; it does not imply broad fixture coverage or behavioral equivalence. See the
[language matrix](REAMON_LANGUAGE_MATRIX.md) for format-level limits.

| Area | Current state | Product gap / next outcome |
| --- | --- | --- |
| Workspace and artifact identity | Implemented: projects/workspaces, targets, imports, artifact hashes, logical paths, and derived provenance records. | Keep source lineage visible from every visualizer unit and export. |
| Provider execution | Implemented for several isolated engines and format-specific adapters. New decompile/disassemble runs attach the input artifact hash and, for bounded saved source files, a centrally calculated output hash to code-unit observations. The visualizer compares up to two hash-verified outputs for the same artifact and source path/language; for native code it also matches canonical function identities across providers whose saved paths or output-language labels differ. It shows a bounded textual line diff and labels both sides as independent evidence. The optional pinned Glaurung analyzer discovers capped native functions and persists hash-attributed per-function C-like pseudocode as REAmon code units. | Persist exact provider options, backfill only where source lineage can be proven, and add fixture-backed output comparison across provider families, including Glaurung against Ghidra. |
| ToCode export import | Implemented for existing ToCode exports: indexed functions, copied source/assembly, project links, and APK field references are stored as REAmon observations. Folder-export input hashes are matched against imported artifact hashes and exposed as provisional provenance in the visualizer; standalone exports without a verifiable input inventory stay unlinked. | Expand APK/.NET metadata and verify project-level mapping and partial-export reporting against representative fixtures. |
| Function / class visualization | Implemented for supported decompiler outputs with code units and relationships. Completed analysis runs remain selectable when they index zero units, with discovered/indexed counts and provider warnings available to explain empty output. | Treat the unit map as the work queue and expose recovery, review, and validation state together. |
| Native source / instruction navigation | Implemented for Ghidra where markup supplies mappings and experimentally for RetDec: mapped source lines are keyboard-accessible and jump to associated instruction addresses in the paired disassembly; multiple addresses on a line can be cycled. Provider-neutral maps and RetDec's bounded raw token evidence are persisted and exposed to MCP. On Mach-O, pinned ReIPA Swift symbols and Objective-C symbol-table or classdump IMP names enrich Ghidra code units only on exact address matches; Swift type and Objective-C interface/category catalogs are stored with exact artifact/run provenance, while ReIPA's early C-like pseudocode is saved as a hash-checked, same-run alternate for exact-address Swift/Objective-C methods. | Compare source/address mapping precision and coverage across Ghidra and RetDec on versioned fixtures; validate ReIPA symbol, pseudocode, and type recovery on arm64 Mach-O fixtures; ensure provider-specific provenance remains visible. |
| Similar function evidence | Implemented for Ghidra, WABT, JADX, ILSpy, and Androguard DEX methods. Bounded instruction-sequence matches can be opened in the visualizer; Android member rewrites resolve matched methods to their class records, load reviewed-source and naming context, and persist source-hash-keyed syntax outlines for precise method excerpts. Selected DEX rewrites also receive their linked Dalvik instructions and typed references. | Measure precision on fixture corpora and keep each candidate tied to its provider, instruction set, artifact hash, and analysis run. |
| Project memory | Implemented: analysis observations and maintenance context are stored and used to ground AI requests. Exact-task call edges identify direct callees separately from callers; direct-callee source snippets, provider signatures, and accepted project symbols are prioritized and labeled in rewrite context. Hash-matched saved drafts for direct callees are also available to later caller rewrites as explicitly provisional source context, with their validation state and output hash; accepted maintained source takes precedence. Accepted symbols are deduplicated by persisted code-unit identity so overloads and same-named units in one artifact remain distinct. Native function identities from Ghidra, Glaurung, and Oxidizer normalize common hexadecimal virtual-address forms for same-artifact cross-provider matching. Rewrite and explanation context now look beyond the newest project-symbol scan for accepted symbols attached to completed provider observations sharing the selected unit's persisted canonical identity and exact input hash; native units also retain raw address-spelling matching for older observations. These names are ranked first and attributed to their provider, with an explicit warning that provider identity and address matches are evidence, not behavioral proof. Accepted-source Tree-sitter outlines retain callable names, kinds, source lines, truncation state, and parser version; rewrite context labels these as file-scoped declarations and explicitly says the outline alone does not prove address-to-function identity. Lua syntax indexing and outlines retain named methods and unambiguous single-target function assignments, so project memory can include common reconstructed Lua member forms. When an accepted source hash exactly matches a successful scope-safe rename attempt, its binding-specific old-to-new mappings are retained with the accepted symbol index, shown in the visualizer's accepted rename history, and returned as reviewed naming context in later AI requests. Bounded project-wide symbol scans disclose when older accepted records may be missing. The prompt permits signatures as call-site evidence while preventing cross-function local-name copying. Exact-address, same-artifact/task ReIPA pseudocode alternatives for matched Swift/Objective-C functions now enter rewrite context as explicitly provisional C-like evidence after path and output-hash verification. | Extend canonical symbol/alias review and stale-context handling across all provider types; carry reviewed callee decisions into later caller requests without making generated names canonical. |
| MCP code-unit context | Implemented: agents can search persisted code units and method-level function observations, then read one bounded dossier with provider/artifact identity, provider-recovered prototype, hash-matched FLOSS stack/tight/decoded string evidence, Ghidra or ToCode parameter/local name and type evidence (Ghidra lock state where available), address-matched GoReSym package identity, and exact-run artifact-wide Go and ToCode type catalogs with name, kind, and reconstructed-form details. Exact-address Swift/Objective-C units expose a same-run ReIPA C-like pseudocode alternate after provider, run-token, address, and output-hash checks; native Ghidra/Glaurung/Oxidizer units can also expose up to three completed cross-provider function outputs when the exact imported binary hash, canonical native address identity, and saved output hash all match. Both forms are explicitly provisional analysis views, not recovered original source. Lua 5.5 and Luau dossiers also expose the detected dialect, input hash, engine version, and any configured vector-constructor assumptions. `workspace_search_go_types` and `workspace_search_provider_types` provide paged access to their respective catalogs while preserving the artifact-wide caveat. Dossiers also include pseudocode, assembly or bytecode, persisted call/member references, bounded instruction/CFG evidence, provider-attributed source-line-to-address mappings, bounded raw RetDec token evidence, source/output-hash draft, maintained source, and a hash-matched review receipt. FLOSS recovered strings plus Ghidra and ToCode recovered variable inventories, plus GoReSym symbol/package provenance, are also available in the selected-unit visualizer inspector. Availability is explicit; no recorded edge is not evidence that a relationship does not exist. DEX methods resolve maintenance/review state through their containing class record. | Improve context paging for very large source units and validate cross-provider matching plus DEX dossiers against representative fixtures. Keep recovered identifiers provider-attributed until explicitly reviewed as canonical. |
| Explanations | Implemented as an AI-assisted workflow with project evidence context. Selected-unit explanations load persisted DEX member references and ToCode `references_field` relationships from the exact analysis task; ToCode references retain unknown access direction and are labeled as provider evidence. | Keep explanations linked to cited code and distinguish facts from inference. |
| Maintainable-source drafts | Implemented for selected source/decompiled-language workflows. Rewrites persist the complete request and project context as queued database attempts; the worker claims them with a run token, renews the source lease during provider calls, and the visualizer polls the authorized job status endpoint. Queued work survives webapp or worker restarts; running work can be cancelled, and an interrupted call is recorded and can be retried. The bounded dispatcher prioritizes queued whole-unit attempts for known same-run callees before callers and holds a caller while a known callee attempt is queued or running; cycles retain FIFO order, and member-scoped attempts retain FIFO scheduling. After a callee finishes, a caller may receive its exact-run saved draft as explicitly provisional source context only when the persisted draft hash matches the source bytes; accepted maintained source takes precedence, and unreviewed names are not promoted to canonical project symbols. Completed attempts can be restored into the editor; member results merge only when their exact input occurs once in the current source. Before accept or reject, the editor can show added and removed lines against the saved maintained version, or the original decompilation when none exists; diff work and display are bounded. Late responses must still own the source-version lease, run token, and uncancelled attempt before saving. A saved draft links to its originating successful attempt; provider and validation metadata are loaded from that record and checked against the draft output. Ghidra and ToCode recovered signatures plus parameter/local names and types, same-function GoReSym package identity, and GoReSym and ToCode type declarations whose exact names occur in the selected function source/signature now join rewrite context as explicitly provisional provider evidence, separate from reviewed project symbols. The JavaScript/TypeScript visualizer now requests bounded rename proposals through the saved model with accepted project symbols, lets the reviewer select them, applies selected mappings through Babel's scope-aware rename API in the isolated analyzer, protects ES-module exports, and saves the input, mapping rationales, output, hashes, and parser version as an attempt and draft. Recovered type declarations remain structural evidence, not behavior facts; JavaScript parse success also remains structural evidence, not behavior proof. | Preserve lineage through draft revisions and accepted reviews; compare the Babel-based first slice with OXC and extend database-grounded, deterministic syntax-aware refactoring to additional languages. |
| Scope-safe source renames | JavaScript and TypeScript use Babel scope binding metadata and AST renames. Python uses LibCST 1.9.0 to catalog function-local variables and parameters, then applies reviewer-selected mappings through its qualified-name scope provider. Go uses the pinned Go toolchain's `go/ast` and `go/types` object identity to catalog referenced local bindings and parameters. Java now uses the JDK `javac` Trees API to catalog local variables, lambda parameters, and private method/constructor parameters, then reparses renamed source and checks references against their original declarations. C# uses Roslyn semantic binding to catalog single-file local symbols, reparses renamed output, and verifies catalogued references still resolve to their corresponding declarations; Roslyn also validates accepted C# source structurally. Standard Lua now has an early LuaLS 3.19.2 adapter: it catalogs semantic local declarations and references, asks LuaLS for selected binding edits, rejects cross-file edits and names already present in the source, and reparses with Tree-sitter. Rust now uses the pinned rust-analyzer 2026-10-12 LSP for same-file local binding references and rename edits in a temporary one-file project; it rejects macro invocations, `cfg` variants, external modules, and custom attributes until complete project context is available. Every path records exact input/output hashes, rationales, mappings, and parser/tool versions as a database attempt; accepted rename mappings join the hash-matched project-memory alias path. Luau remains unsupported by the LuaLS path and requires its own semantic backend. | Java, Roslyn C#, LuaLS, and rust-analyzer paths are early and have not been compared against fixture corpora. Measure Java capture across nested blocks and lambda scopes, C# shadowing, Lua shadowing/closures/loop variables/method syntax, and Rust nested scopes, pattern bindings, edition keywords, and UTF-16 positions before widening use. Structural parsing does not prove behavior where reflection, dynamic lookup, interfaces, or external APIs affect semantics. |
| Review and acceptance | Saving maintained source or Smali requires a rationale and creates an immutable acceptance receipt tied to reviewer ID, time, and the exact maintained-source hash. JavaScript and TypeScript accepted source up to 512 KiB is checked by the same versioned Babel parser used for scope-safe renames; if that service is unavailable or the source is larger, validation falls back to the versioned Tree-sitter grammar path. Smali acceptance is checked by the pinned 3.0.10 assembler in the isolated Android analyzer, which must produce a DEX file for the selected class; the exact source hash, assembler version, result, and message are stored on the receipt. Maintained-source receipts persist the validator status, method, and message; accepted source with syntax errors is rejected, and a later save cannot replace a previously validated accepted version when validation becomes unavailable. Draft rejection creates a separate hash-bound receipt with reviewer rationale; future rewrite prompts receive recent rejection feedback as untrusted context. A source-hash compare-and-swap guard rejects stale concurrent promotions before recording acceptance. The visualizer and MCP show the receipt’s structural validation evidence, and rewrite/safe-rename context carries that status with accepted project symbols. Run coverage counts only receipts that match the saved source hash. AI project memory verifies the acceptance receipt pointer and hash before using maintained source or its symbols. | Add explicit rollback/revoke decisions and compiler/build-level validation regression guards; keep unreviewed attempts distinct from accepted maintained source. |
| Validation | Rewrite attempts and maintained-source acceptance receipts persist validator status, method, and message tied to the exact source hash. JavaScript and TypeScript accepted source up to 512 KiB is parsed by the pinned Babel parser; if Babel is unavailable or the source is larger, validation falls back to Tree-sitter. Tree-sitter syntax checks record the selected grammar and Tree-sitter Language Pack version, preserve recognized callable counts across supported grammars, and Java and C/C++ also retain their existing declaration-shape checks. Python uses non-executing CPython `compile()`; PHP uses `php -l`; Ruby uses `ruby -c`; Go uses `gofmt -e` with parsed output discarded; exact Lua 5.1–5.5 dialects use checksum-pinned official `luac -p` compilers; amd64 images use pinned Luau 0.742 `luau-compile --only-parse`, with Tree-sitter fallback where that binary is unavailable. These checks record their runtime/tool versions and exact input hashes, and PHP without an opening tag is explicitly unavailable. All syntax results are structural evidence, separate from behavior proof. Saved drafts persist an output hash; run coverage counts only whole-file validation records whose exact output hash matches the current reviewed source. Older drafts without that fingerprint are surfaced as unmatched/unknown. Editing a saved draft clears its old validation metadata and refreshes its output hash. | Add target-version Python checks and language-specific compiler/build, differential, and runtime validators; keep every result tied to the exact validated output and source artifact hashes. |
| Decompilation coverage | Run metrics distinguish indexed units from analyzer-reported discovered units, expose known discovered units that lack indexed records, truncation, and failed functions, and compute decompilation completeness over measured bytes. The visualizer shows how much indexed code size is measured so a high completeness score cannot hide a large unmeasured portion. | Persist a provider-independent inventory of eligible, unsupported, excluded, truncated, skipped, and failed units so every provider's coverage can use the same explicit denominator. |
| Language and format support | Mixed: usable Java/.NET, low-level WebAssembly, early Python/JavaScript/Lua and Go metadata support (GoReSym plus unstrip type, signature, source-location, and interface-dispatch recovery), early independent JVM outputs from Vineflower and CFR, hash-verified alternate class/method context for AI rewrites, an early optional Rust-like pseudocode provider (Oxidizer via angr 10.0.4), and partial generic native pseudocode. | Use [the language matrix](REAMON_LANGUAGE_MATRIX.md) as the single detailed status ledger and validate each row with fixtures. Compare CFR, Vineflower, and JADX on versioned Java fixtures; Vineflower's Kotlin plugin still needs Kotlin/JVM corpus comparisons, and Android DEX remains on Java-like output. Go's unstrip metadata passes need fixture comparison and source-location checks; Oxidizer needs compiler-versioned, stripped/debug, optimization, and architecture comparisons with Ghidra before its recovery quality can be claimed. |
| Concurrent agent work | Same-unit AI rewrites use a database lease scoped to project, artifact, run, code unit, and exact source hash; queued attempts are claimed with run-token fencing, active source-lease heartbeats, cancellation, and stale recovery. Maintained-source and Smali promotions compare the loaded hash inside a transaction; stale collisions return a conflict without replacing the current source or receipt. General analysis tasks have owner IDs, run-token fencing, heartbeat renewal, operator cancellation, and stale recovery. | Add cancellation acknowledgements in attempt history; guard external derived-file edits and validation regressions. |
| Reproducible project export | The source bundle keeps provider decompilation and maintained source in separate trees. Its manifest includes input-artifact identity/hash, registered provider ID/version, per-unit engine version when the analyzer recorded one, and per-file SHA-256 values. It verifies acceptance receipts against project, artifact, unit, accepted decision, and exact exported source hash. For accepted source, it links a saved whole-file draft from the same run only when its output hash matches, then records its input hash, provider/model, validator, and source-attempt lineage; attempt output hashes are checked against draft hashes. Ghidra bundles additionally contain a bounded `native-annotations.json` sidecar with accepted symbol inventories, function addresses, exact binary hash, and review provenance. Where the accepted source has exactly one Tree-sitter-outlined C function declaration, the bundle also includes a Ghidra script that checks the loaded executable's SHA-256 and the function's original name before applying that accepted declaration name at the original Ghidra address; it never rebases. Both sidecar and script hashes/truncation are recorded in the main manifest. This first importer path has not been validated against a Ghidra fixture yet. Draft lookup is capped at 50,000 rows and reports truncation. Missing, unavailable, or mismatched evidence is labeled. | Validate the importer against exact-binary fixtures and add IDA support; expand source declaration mappings only when syntax provides an unambiguous function-to-address relationship. Persist the actual engine version for every provider and include a reproducible rebuild or validation recipe where a supported toolchain exists. |
| Dynamic analysis | Existing platform-specific work exists in the wider REAmon repository. | Connect runtime observations to static units and the same project identity model without requiring dynamic analysis for basic decompilation. |

## Product-critical distinctions

- Decompilation output and AI-maintained source are separate artifacts.
- A completed provider task is not proof of full analysis coverage.
- A parsed candidate is not necessarily compilable; a compiled candidate is not
  necessarily behaviorally equivalent.
- A recovered name is a proposal until its evidence and review state are recorded.
- Similarity helps locate useful examples, but project identity and behavioral claims
  require stronger evidence.

For the intended process and state model, see [the workflow](REAMON_WORKFLOW.md).
