# REAmon feature matrix

This matrix describes product capabilities, not a promise that every engine or input
works for every artifact. “Implemented” means a workflow exists in the current
checkout; it does not imply broad fixture coverage or behavioral equivalence. See the
[language matrix](REAMON_LANGUAGE_MATRIX.md) for format-level limits.

| Area | Current state | Product gap / next outcome |
| --- | --- | --- |
| Workspace and artifact identity | Implemented: projects/workspaces, targets, imports, artifact hashes, logical paths, and derived provenance records. | Keep source lineage visible from every visualizer unit and export. |
| Provider execution | Implemented for several isolated engines and format-specific adapters. | Persist exact provider options and make alternate outputs comparable side by side. |
| Function / class visualization | Implemented for supported decompiler outputs with code units and relationships. Completed analysis runs remain selectable when they index zero units, with discovered/indexed counts and provider warnings available to explain empty output. | Treat the unit map as the work queue and expose recovery, review, and validation state together. |
| Native source / instruction navigation | Implemented for Ghidra where markup supplies mappings: mapped source lines are keyboard-accessible and jump to associated p-code target addresses in the paired disassembly; multiple addresses on a line can be cycled. Maps are persisted with the selected code-unit dossier and exposed to MCP. | Extend line/address mappings to other native decompilers and add fixture-backed validation that displayed source lines and listing addresses stay aligned. |
| Similar function evidence | Implemented for Ghidra, WABT, JADX, ILSpy, and Androguard DEX methods. Bounded instruction-sequence matches can be opened in the visualizer; Android member rewrites resolve matched methods to their class records, load reviewed-source and naming context, and persist source-hash-keyed syntax outlines for precise method excerpts. Selected DEX rewrites also receive their linked Dalvik instructions and typed references. | Measure precision on fixture corpora and keep each candidate tied to its provider, instruction set, artifact hash, and analysis run. |
| Project memory | Implemented: analysis observations and maintenance context are stored and used to ground AI requests. Exact-task call edges identify direct callees separately from callers; direct-callee source snippets, provider signatures, and accepted project symbols are prioritized and labeled in rewrite context. When an accepted source hash exactly matches a successful scope-safe rename attempt, its binding-specific old-to-new mappings are retained with the accepted symbol index, shown in the visualizer's accepted rename history, and returned as reviewed naming context in later AI requests. Bounded project-wide symbol scans disclose when older accepted records may be missing. The prompt permits signatures as call-site evidence while preventing cross-function local-name copying. | Extend canonical symbol/alias review and stale-context handling across all provider types; carry reviewed callee decisions into later caller requests without making generated names canonical. |
| MCP function context | Implemented: agents can search persisted code units and method-level function observations, then read one bounded dossier with provider/artifact identity, provider-recovered prototype, Ghidra or ToCode parameter/local name and type evidence (Ghidra lock state where available), address-matched GoReSym package identity, and exact-run artifact-wide Go and ToCode type catalogs with name, kind, and reconstructed-form details. `workspace_search_go_types` and `workspace_search_provider_types` provide paged access to their respective catalogs while preserving the artifact-wide caveat. Dossiers also include pseudocode, assembly or bytecode, persisted call/member references, bounded instruction/CFG evidence, Ghidra source-line-to-p-code-address mappings, source/output-hash draft, maintained source, and a hash-matched review receipt. Ghidra and ToCode recovered variable inventories, plus GoReSym symbol/package provenance, are also available in the selected-unit visualizer inspector. Availability is explicit; no recorded edge is not evidence that a relationship does not exist. DEX methods resolve maintenance/review state through their containing class record. | Improve context paging for very large source units and validate DEX dossiers against representative APK fixtures. Keep recovered identifiers provider-attributed until explicitly reviewed as canonical. |
| Explanations | Implemented as an AI-assisted workflow with project evidence context. Selected-unit explanations load persisted DEX member references and ToCode `references_field` relationships from the exact analysis task; ToCode references retain unknown access direction and are labeled as provider evidence. | Keep explanations linked to cited code and distinguish facts from inference. |
| Maintainable-source drafts | Implemented for selected source/decompiled-language workflows. Rewrites persist the complete request and project context as queued database attempts; the worker claims them with a run token, renews the source lease during provider calls, and the visualizer polls the authorized job status endpoint. Queued work survives webapp or worker restarts; running work can be cancelled, and an interrupted call is recorded and can be retried. The bounded dispatcher prioritizes queued whole-unit attempts for known same-run callees before callers and holds a caller while a known callee attempt is queued or running; cycles retain FIFO order, and member-scoped attempts retain FIFO scheduling. This only orders outstanding attempts: a completed draft is not treated as a reviewed symbol or automatically injected into a later request. Completed attempts can be restored into the editor; member results merge only when their exact input occurs once in the current source. Before accept or reject, the editor can show added and removed lines against the saved maintained version, or the original decompilation when none exists; diff work and display are bounded. Late responses must still own the source-version lease, run token, and uncancelled attempt before saving. A saved draft links to its originating successful attempt; provider and validation metadata are loaded from that record and checked against the draft output. Ghidra and ToCode recovered signatures plus parameter/local names and types, same-function GoReSym package identity, and GoReSym and ToCode type declarations whose exact names occur in the selected function source/signature now join rewrite context as explicitly provisional provider evidence, separate from reviewed project symbols. The JavaScript/TypeScript visualizer now requests bounded rename proposals through the saved model with accepted project symbols, lets the reviewer select them, applies selected mappings through Babel's scope-aware rename API in the isolated analyzer, protects ES-module exports, and saves the input, mapping rationales, output, hashes, and parser version as an attempt and draft. Recovered type declarations remain structural evidence, not behavior facts; JavaScript parse success also remains structural evidence, not behavior proof. | Preserve lineage through draft revisions and accepted reviews; compare the Babel-based first slice with OXC and extend database-grounded, deterministic syntax-aware refactoring to additional languages. |
| Review and acceptance | Saving maintained source or Smali requires a rationale and creates an immutable acceptance receipt tied to reviewer ID, time, and the exact maintained-source hash. JavaScript and TypeScript accepted source up to 512 KiB is checked by the same versioned Babel parser used for scope-safe renames; if that service is unavailable or the source is larger, validation falls back to the versioned Tree-sitter grammar path. Maintained-source receipts persist the validator status, method, and message; accepted source with syntax errors is rejected, and a later save cannot replace a previously syntax-passing accepted version when validation becomes unavailable. Draft rejection creates a separate hash-bound receipt with reviewer rationale; future rewrite prompts receive recent rejection feedback as untrusted context. A source-hash compare-and-swap guard rejects stale concurrent promotions before recording acceptance. The visualizer and MCP show the receipt’s structural validation evidence, and rewrite/safe-rename context carries that status with accepted project symbols. Run coverage counts only receipts that match the saved source hash. AI project memory verifies the acceptance receipt pointer and hash before using maintained source or its symbols. | Add explicit rollback/revoke decisions and compiler/build-level validation regression guards; keep unreviewed attempts distinct from accepted maintained source. |
| Validation | Rewrite attempts and maintained-source acceptance receipts persist validator status, method, and message tied to the exact source hash. JavaScript and TypeScript accepted source up to 512 KiB is parsed by the pinned Babel parser; if Babel is unavailable or the source is larger, validation falls back to Tree-sitter. Tree-sitter syntax checks record the selected grammar and Tree-sitter Language Pack version, preserve recognized callable counts across supported grammars, and Java and C/C++ also retain their existing declaration-shape checks. Python uses non-executing CPython `compile()`; PHP uses `php -l`; Ruby uses `ruby -c`; Go uses `gofmt -e` with parsed output discarded. These checks record their runtime/tool versions and exact input hashes, and PHP without an opening tag is explicitly unavailable. All syntax results are structural evidence, separate from behavior proof. Saved drafts persist an output hash; run coverage counts only whole-file validation records whose exact output hash matches the current reviewed source. Older drafts without that fingerprint are surfaced as unmatched/unknown. Editing a saved draft clears its old validation metadata and refreshes its output hash. | Add target-version Python checks and language-specific compiler/build, differential, and runtime validators; keep every result tied to the exact validated output and source artifact hashes. |
| Decompilation coverage | Run metrics distinguish indexed units from analyzer-reported discovered units, expose known discovered units that lack indexed records, truncation, and failed functions, and compute decompilation completeness over measured bytes. The visualizer shows how much indexed code size is measured so a high completeness score cannot hide a large unmeasured portion. | Persist a provider-independent inventory of eligible, unsupported, excluded, truncated, skipped, and failed units so every provider's coverage can use the same explicit denominator. |
| Language and format support | Mixed: usable Java/.NET, low-level WebAssembly, early Python/JavaScript/Lua and Go metadata support, an early optional Rust-like pseudocode provider (Oxidizer via angr 10.0.4), and partial generic native pseudocode. | Use [the language matrix](REAMON_LANGUAGE_MATRIX.md) as the single detailed status ledger and validate each row with fixtures. Oxidizer needs compiler-versioned, stripped/debug, optimization, and architecture comparisons with Ghidra before its recovery quality can be claimed. |
| Concurrent agent work | Same-unit AI rewrites use a database lease scoped to project, artifact, run, code unit, and exact source hash; queued attempts are claimed with run-token fencing, active source-lease heartbeats, cancellation, and stale recovery. Maintained-source and Smali promotions compare the loaded hash inside a transaction; stale collisions return a conflict without replacing the current source or receipt. General analysis tasks have owner IDs, run-token fencing, heartbeat renewal, operator cancellation, and stale recovery. | Add cancellation acknowledgements in attempt history; guard external derived-file edits and validation regressions. |
| Reproducible project export | The source bundle keeps provider decompilation and maintained source in separate trees. Its manifest includes input-artifact identity/hash, registered provider ID/version, per-unit engine version when the analyzer recorded one, and per-file SHA-256 values. It verifies acceptance receipts against project, artifact, unit, accepted decision, and exact exported source hash. For accepted source, it links a saved whole-file draft from the same run only when its output hash matches, then records its input hash, provider/model, validator, and source-attempt lineage; attempt output hashes are checked against draft hashes. Draft lookup is capped at 50,000 rows and reports truncation. Missing, unavailable, or mismatched evidence is labeled. | Persist the actual engine version for every provider and include a reproducible rebuild or validation recipe where a supported toolchain exists. |
| Dynamic analysis | Existing platform-specific work exists in the wider REAmon repository. | Connect runtime observations to static units and the same project identity model without requiring dynamic analysis for basic decompilation. |

## Product-critical distinctions

- Decompilation output and AI-maintained source are separate artifacts.
- A completed provider task is not proof of full analysis coverage.
- A parsed candidate is not necessarily compilable; a compiled candidate is not
  necessarily behaviorally equivalent.
- A recovered name is a proposal until its evidence and review state are recorded.
- Similarity helps locate useful examples, but project identity and behavioral claims
  require stronger evidence.

For the intended process and state model, see [the workflow](REAMON_WORKFLOW.md).
