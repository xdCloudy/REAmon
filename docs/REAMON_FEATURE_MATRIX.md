# REAmon feature matrix

This matrix describes product capabilities, not a promise that every engine or input
works for every artifact. “Implemented” means a workflow exists in the current
checkout; it does not imply broad fixture coverage or behavioral equivalence. See the
[language matrix](REAMON_LANGUAGE_MATRIX.md) for format-level limits.

| Area | Current state | Product gap / next outcome |
| --- | --- | --- |
| Workspace and artifact identity | Implemented: projects/workspaces, targets, imports, artifact hashes, logical paths, and derived provenance records. | Keep source lineage visible from every visualizer unit and export. |
| Provider execution | Implemented for several isolated engines and format-specific adapters. | Persist exact provider options and make alternate outputs comparable side by side. |
| Function / class visualization | Implemented for supported decompiler outputs with code units and relationships. | Treat the unit map as the work queue and expose recovery, review, and validation state together. |
| Native source / instruction navigation | Implemented for Ghidra where markup supplies mappings: mapped source lines are keyboard-accessible and jump to associated p-code target addresses in the paired disassembly; multiple addresses on a line can be cycled. Maps are persisted with the selected code-unit dossier and exposed to MCP. | Extend line/address mappings to other native decompilers and add fixture-backed validation that displayed source lines and listing addresses stay aligned. |
| Similar function evidence | Implemented for Ghidra, WABT, JADX, ILSpy, and Androguard DEX methods. Bounded instruction-sequence matches can be opened in the visualizer; Android member rewrites resolve matched methods to their class records, load reviewed-source and naming context, and persist source-hash-keyed syntax outlines for precise method excerpts. Selected DEX rewrites also receive their linked Dalvik instructions and typed references. | Measure precision on fixture corpora and keep each candidate tied to its provider, instruction set, artifact hash, and analysis run. |
| Project memory | Implemented: analysis observations and maintenance context are stored and used to ground AI requests. | Establish canonical symbol/alias review and stale-context handling across all provider types. |
| MCP function context | Implemented: agents can search persisted code units and method-level function observations, then read one bounded dossier with provider/artifact identity, provider-recovered prototype, Ghidra or ToCode parameter/local name and type evidence (Ghidra lock state where available), address-matched GoReSym package identity, and the exact-run artifact-wide Go type catalog with name, kind, and reconstructed-form details. `workspace_search_go_types` searches and pages that catalog for a selected function’s exact run while preserving the artifact-wide caveat. Dossiers also include pseudocode, assembly or bytecode, persisted call/member references, bounded instruction/CFG evidence, Ghidra source-line-to-p-code-address mappings, source/output-hash draft, maintained source, and a hash-matched review receipt. Ghidra and ToCode recovered variable inventories, plus GoReSym symbol/package provenance, are also available in the selected-unit visualizer inspector. Availability is explicit; no recorded edge is not evidence that a relationship does not exist. DEX methods resolve maintenance/review state through their containing class record. | Add provider-backed facets where absent; improve context paging for very large source units and validate DEX dossiers against representative APK fixtures. Keep recovered identifiers provider-attributed until explicitly reviewed as canonical. |
| Explanations | Implemented as an AI-assisted workflow with project evidence context. | Keep explanations linked to cited code and distinguish facts from inference. |
| Maintainable-source drafts | Implemented for selected source/decompiled-language workflows. Rewrites persist the complete request and project context as queued database attempts; the worker claims them with a run token, renews the source lease during provider calls, and the visualizer polls the authorized job status endpoint. Queued work survives webapp or worker restarts; running work can be cancelled, and an interrupted call is recorded and can be retried. Completed attempts can be restored into the editor; member results merge only when their exact input occurs once in the current source. Late responses must still own the source-version lease, run token, and uncancelled attempt before saving. A saved draft links to its originating successful attempt; provider and validation metadata are loaded from that record and checked against the draft output. Ghidra and ToCode recovered signatures plus parameter/local names and types, same-function GoReSym package identity, and GoReSym reconstructed type records whose exact names occur in the selected Go function source/signature now join rewrite context as explicitly provisional provider evidence, separate from reviewed project symbols. The JavaScript/TypeScript visualizer now requests bounded rename proposals through the saved model with accepted project symbols, lets the reviewer select them, applies selected mappings through Babel's scope-aware rename API in the isolated analyzer, and saves the input, mapping rationales, output, hashes, and parser result as an attempt and draft. Go types remain structural evidence, not behavior facts; JavaScript parse success also remains structural evidence, not behavior proof. | Preserve lineage through draft revisions and accepted reviews; compare the Babel-based first slice with OXC and extend database-grounded, deterministic syntax-aware refactoring to additional languages. |
| Review and acceptance | Saving maintained source or Smali requires a rationale and creates an immutable acceptance receipt tied to reviewer ID, time, and the exact maintained-source hash. A source-hash compare-and-swap guard rejects stale concurrent promotions before recording a receipt. The visualizer shows recent receipt history and run coverage counts only receipts that still match the saved source hash. AI project memory verifies the receipt pointer and hash before using maintained code or its symbols. | Add rejection receipts, explicit rollback/revoke decisions, and validation regression guards; keep unreviewed attempts distinct from accepted maintained source. |
| Validation | Rewrite attempts persist validator status, method, and message. Tree-sitter syntax checks preserve recognized callable counts across supported grammars; Java and C/C++ also retain their existing declaration-shape checks. These results are labeled as structural evidence, separate from behavior proof. Saved drafts now persist an output hash; run coverage counts only whole-file validation records whose exact output hash matches the current reviewed source. Older drafts without that fingerprint are surfaced as unmatched/unknown. Editing a saved draft clears its old validation metadata and refreshes its output hash. | Add language-specific compiler/build, differential, and runtime validators; keep every result tied to the exact validated output and source artifact hashes. |
| Decompilation coverage | Metrics exist for selected providers and run scopes. | Use a stable denominator with explicit excluded, unsupported, truncated, and failed units. |
| Language and format support | Mixed: usable Java/.NET, low-level WebAssembly, early Python/JavaScript/Lua and Go metadata support, an early optional Rust-like pseudocode provider (Oxidizer via angr 10.0.4), and partial generic native pseudocode. | Use [the language matrix](REAMON_LANGUAGE_MATRIX.md) as the single detailed status ledger and validate each row with fixtures. Oxidizer needs compiler-versioned, stripped/debug, optimization, and architecture comparisons with Ghidra before its recovery quality can be claimed. |
| Concurrent agent work | Same-unit AI rewrites use a database lease scoped to project, artifact, run, code unit, and exact source hash; queued attempts are claimed with run-token fencing, active source-lease heartbeats, cancellation, and stale recovery. Maintained-source and Smali promotions compare the loaded hash inside a transaction; stale collisions return a conflict without replacing the current source or receipt. General analysis tasks have owner IDs, run-token fencing, heartbeat renewal, operator cancellation, and stale recovery. | Add cancellation acknowledgements in attempt history; guard external derived-file edits and validation regressions. |
| Reproducible project export | Export workflows exist for selected maintained source and Android resource/Smali cases. | Export consistent source plus evidence manifest and a reproducible rebuild/validation recipe where possible. |
| Dynamic analysis | Existing platform-specific work exists in the wider REAmon repository. | Connect runtime observations to static units and the same project identity model without requiring dynamic analysis for basic decompilation. |

## Product-critical distinctions

- Decompilation output and AI-maintained source are separate artifacts.
- A completed provider task is not proof of full analysis coverage.
- A parsed candidate is not necessarily compilable; a compiled candidate is not
  necessarily behaviorally equivalent.
- A recovered name is a proposal until its evidence and review state are recorded.
- Similarity helps locate useful examples, but project identity and behavioral claims
  require stronger evidence.

For the intended process and state model, see [the workflow](REAMON_WORKFLOW.md).
